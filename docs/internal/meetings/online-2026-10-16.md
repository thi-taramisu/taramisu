### 2. Architecture & Concept Discussions

- **UI/UX Workflow & TARA Compliance:**
  - *Context:* The current wireframe concept relies on a strictly hierarchical structure.
  - *Standard Requirements:* In ISO/SAE 21434, assets do not have a single mandatory origin; they can be created directly from the
    Item Definition, derived from an Impact Rating, or identified via a Threat Scenario.
  - *Discussion:* The team discussed whether the UI should reflect this multi-entry model or enforce a guided flow. It was noted that the
    standard's "can" phrasing allows flexible entry points without strictly mandating them.
  - *User Guidance vs. Flexibility:* The application should primarily provide clear guidance and orientation for the user rather than
    overwhelming them with ambiguity, while still supporting standard-compliant workflows.
  - *Proposed Solutions:* Offering multiple entry points across the interface or introducing a mode toggle (e.g., a guided "Simple View"
    vs. an "Expert View").
  - *Next Steps:* The UX team working on related tickets will prepare a concrete proposal based on this discussion.
- **IAM Data Modeling & User Persistence (Issue #50):**
  - *Context:* Issue #50 provides a proposed schema for the IAM data model.
  - *Discussion:* The team debated whether user data (e.g., display name, profile attributes) should reside exclusively in the IAM system
    or whether basic user information should be stored redundantly and be editable within the application database.
  - *Trade-offs:* Clear separation of concerns and a single source of truth (IAM-only) vs. application decoupling and reduced dependency
    on external IAM tool APIs for everyday user display.
  - *Next Steps:* The directly involved team members will align in a focused sync to finalize the decision prior to the next weekly meeting.
