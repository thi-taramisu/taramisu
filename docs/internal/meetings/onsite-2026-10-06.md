### 3. Workflow Discussions

- **Customer Constraints:** Strictly "no vibe-coding".
- **Workflow:** Work must be managed using smaller tickets, accompanied by compact, focused commits.
- **Pull Requests:** A default Pull Request Template should be used.
- **Testing:** Every implementation strictly requires tests (for both frontend and backend). The team needs to discuss whether to officially adopt Test-Driven Development.

### 4. Documentation Strategy

- **Format:** All documentation will be written in Markdown. Tools like *Docusaurus* might be considered (see the Discord channel for ideas).
- **Approval Process:** Every team member shall have the chance to review meeting notes and other documents that are relevant to the whole group using a Pull Request. The Pull Request shall stay open for at least 24h or until everyone has approved it before merging.
- **Repository Structure:**
  * `docs/external`: User and customer documentation.
  * `docs/internal`: Internal documents, including guides, workflow procedures (e.g., Contribution Guide), and meeting notes.
